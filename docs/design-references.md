# Otoha design references

Reviewed November 22, 2026. Three recent Awwwards Sites of the Day informed the design direction for the native remote.

**Preymaker · November 14.** A mountain photograph contracts into the silhouette of the studio’s bird mark, revealing a quiet page of partner credits. The mark does a job during the transition. For Otoha, the waveform on the app icon can identify the remote at rest, and its amber accent can carry through to the moving fader. Keep the controls available immediately and preserve a still version for Reduce Motion. [Awwwards award record](https://www.awwwards.com/sites/preymaker) · [Recorded mask transition](https://www.awwwards.com/inspiration/mask-transition-preymaker)

**ViV · November 6.** Lundqvist & Dallyn built the identity around the logo and turned a nested artist roster into a visual grid. The useful part for a remote is recognition at a glance. Give Phono, TV, and More inputs consistent positions and visible names. Leave the larger volume surface easy to find by feel. [Awwwards award record](https://www.awwwards.com/sites/viv) · [Studio case study](https://www.lundqvistdallyn.studio/work/viv)

**Spyker Cars · October 30.** The configurator pairs hotspots on the car with focused option sheets. Choosing a paint color changes the car in view. For Otoha, place recognizable models where their functions live. A front-panel light can echo receiver connectivity, and the shape of the BroadLink hub can identify the infrared wake path. Pair each visual with a text label so the same information is available with VoiceOver. [Awwwards award record](https://www.awwwards.com/sites/spyker-cars) · [Designer’s configurator walkthrough](https://thomasgertenbach.com/work/spyker)

### Blender workflow

From the Otoha repository, start the installed MCP extension on loopback with the library open. On macOS the Blender executable is normally at `/Applications/Blender.app/Contents/MacOS/Blender`.

```sh
blender --background "design/Otoha Hardware.blend" --command blender_mcp
```

1. Use MCP to select the product scene, inspect its objects and capture the current camera with `render_viewport_to_path`. This also works headlessly.
2. Compare the intended camera view with the product manual or manufacturer photograph. Edit [the mesh generator](../design/hardware.py), [model aliases](../design/hardware_catalog.py) or [the paired shot](../design/study.py).
3. Rebuild with `blender -b --factory-startup --python-exit-code 1 -P design/hardware.py`. The build exports each GLB, imports it into a clean scene and renders the portrait used by both apps. Append `-- HK3770 RMmini3` for a quick preview of those models. A full run also writes the editable library, shared catalog and paired still.
4. Run `python3 design/board.py` with Pillow installed to compose the board. Check the changed identities in the running web remote and iPhone simulator at the equipment plate’s normal display size. An isolated bridge fixture can supply the model and blaster labels.
